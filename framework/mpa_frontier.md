# MPA — FRONTIER (maturity ledger)

The fourth axis. The other three say *what is claimed* (engine), *how it is derived* (receipts), *what is borrowed* (prior-art). This one says **how settled each thing is, and exactly what would move it.** It is the single source of truth for everything not yet load-bearing. Its job is not to feed the core — it is to keep provisional work **out** of the core until it earns in. Structure here is quarantine, not on-ramp.

The value of the engine is that everything in it is committed. That guarantee survives only if the line below is strict.

---

## GATES — the state machine (binding)

Five rungs and a hard line. An item occupies **exactly one rung at one time**; moving rungs is an explicit event with a **recorded trigger** (no session-lore promotions).

```
steeping ──▶ sharpening ──▶ battery ──▶ staked ──╮
   │             │             │           │      │  COMMIT LINE
   ▼             ▼             ▼           ▼      ▼  ───────────────
 discarded (tombstone) at any rung         promoted → engine / receipts / prior-art
```

**Promotion gates** (the condition to cross each boundary — strict, and these are the framework's own rules, not new ones):
- `steeping → sharpening` — the speculation acquires *either* a concrete mechanism *or* a way to test it (a named owed item, or a candidate spec). Pure intuition with neither stays steeping.
- `sharpening → battery` — a runnable falsifier spec exists: finite-operating-point, a **forced-not-fitted** target, and explicit kill **and** vindicate conditions.
- `battery → staked` — the spec is planted in the receipts as a falsifier of record (the `staked` tag), un-instanced by design.
- `staked → promoted` **(crosses the line)** — requires *all* of: (a) a **real cross-substrate instance**, not synthetic — a synthetic pass is calibration, never vindication; OR for a non-instance claim, a **forced-not-fitted derivation**; (b) **goalpost-optic** — the move shrinks the falsifiable surface, never enlarges it; (c) for a refinement that *defends* an existing claim rather than *adds* one, a **second independent instance**. The promotion records what crossed, the evidence, and which core doc absorbed it.

**Demotion / kill gates:**
- Any item whose promotion gate is disproven → `discarded`, with a one-line **tombstone** (what it was, why it died) so it is never silently re-explored.
- A `staked` falsifier that **fires** does not just demote — it **kills the core claim it defended**; the kill propagates into engine/receipts. Falsifiers are load-bearing in both directions.

**Schema (mandatory).** Every register entry carries five fields. An entry missing any field is malformed and may not be added:
`key` **[rung]** — *verdict* (current belief, one line) · **↑** promote-gate · **✗** kill-condition · **→** core target (the claim it becomes / the falsifier it operationalizes), or `pure-exploration` if it has no target yet (permitted **only** at the steeping rung).

---

## INVARIANTS — auditable (the discipline, mechanized)

- **I1 — bridge integrity.** Every `staked` entry in the receipts ↔ exactly one frontier entry at the `[staked]` rung. The staked rung is the only place an item is simultaneously in the core and on the frontier; it must reconcile both ways.
- **I2 — no orphans.** Every frontier entry has a `→` core target, *or* is flagged `pure-exploration` (steeping rung only). Nothing floats.
- **I3 — purity of the core.** Nothing above the commit line lives in a working file; nothing below it lives in engine/receipts/prior-art. The core contains only what crossed.
- **I4 — recorded triggers.** No rung change without a logged trigger meeting the named gate. Absence of a trigger = the move did not happen.

(I1 and I2 are checkable mechanically against the receipts, the same way the prior-art map is.)
